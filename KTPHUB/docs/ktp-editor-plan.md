## Часть A. Правки редактора

### A1. Ссылки на законы РК / приложение ТУП (источник — test_ru.json)
- **Задача.** При создании КТП по предмету подставляется корректный источник (приказ/приложение) и ссылка для каждой пары «предмет × класс».
- **Контекст Desktop.** Источник уже подтягивается в редакторе (`KtpEditor.tsx`, поиск `sourceDoc` по `subjectId × grade × language` из `tup_documents` + ссылка adilet через `src/lib/adilet.ts`). Данные ТУП в БД — из `Materials/test_ru.json` (там `order_number`, `order_date`, `appendix_number`).
- **Метод решения.**
  1. Эталонный реестр «предмет × класс → приказ/приложение» — из данных `tup_documents` (заполнены из `test_ru.json`). Плюс юнит-тест, проверяющий пару «алгебра 10 класс → приложение» по данным реестра.
  2. Выводить источник везде:
     - при создании КТП из ТУП (панель `KtpList.tsx`/шаг генерации);
     - в шапке редактора КТП — уже есть, дополнить формой «Источник: приказ МОН РК от {дата} № {номер} · приложение {n} · [ссылка]»;
     - при подстановке в пояснительную записку/титульный лист (нормативная база).
  3. Если пары нет в БД — «источник не определён», универсальную ссылку не подставлять.
- **Что решает.** Юридическая корректность документов; убирает риск сдачи КТП с чужим приложением.
- **Метрики качества.**
  - Для алгебры 10 класса подставляется эталонное приложение из `test_ru.json`, не «общее» значение.
  - Реестр из `test_ru.json` покрыт юнит-тестом.
  - Отсутствие пары → «источник не определён», а не подмена.

### A2. Редактирование — только внутри одной четверти; запрет переноса между разделами
- **Задача.** `reorderPlan` (`editorModel.ts`) позволяет перетащить урок в другой раздел (и другую четверть). Разделы и уроки нельзя перемещать между четвертями — редактирование идёт внутри одной четверти, как распределено в ТУП.
- **Метод решения.**
  1. В `reorderPlan` (или `handleDragEnd` в `KtpEditor.tsx`) определять номер четверти урока (по `QUARTER_HEADER` в плоском плане) и сравнивать у `active` и `over`.
  2. Если четверти разные — операцию не выполнять и показать подсказку.
  3. Перенос между разделами одной четверти — запрещён; внутри раздела — разрешён.
  4. Спец-строки (REPETITION, SOCH, SOR) не двигаются за пределы своей четверти; их `sectionName` не участвует в проверке «раздел совпадает».
- **Что решает.** Целостность методической структуры: урок не «уезжает» в чужой раздел/четверть и не ломает логику СОР/СОЧ.
- **Метрики качества.**
  - Юнит-тест `reorderPlan`: перенос внутри раздела выполняется, между разделами/четвертями — план не меняется.
  - Ручная проверка: перетаскивание в чужой раздел/четверть даёт понятную подсказку.

### A3. Не создавать плашку раздела после СОР
- **Задача.** При перемещении урока под СОР появляется плашка/разделитель с названием раздела (`isSectionEnd`/`isNewSection` в `KtpEditor.tsx`).
- **Метод решения.**
  1. СОР-урок имеет тот же `sectionName`, что и раздел — исключить СОР из логики `isNewSection`/`isSectionEnd`.
  2. Разделитель «Добавить СОР» и плашка конца раздела не должны рисоваться после/внутри СОР.
  3. Сохранить возможность добавить СОР: кнопка доступна на последнем стандартном уроке раздела (или на строке самого СОР — решение при реализации).
- **Что решает.** Чистая визуальная структура таблицы без лишних плашек.
- **Метрики качества.**
  - После СОР (и после урока, перемещённого под СОР) нет плашки раздела.
  - Визуальный чек-лист на реальном плане.

### A4. Урок СОР дублирует тему и цель последнего обычного урока
- **Задача.** При создании СОР в разделе тема/цель СОР должны повторять тему/цель последнего стандартного урока раздела.
- **Метод решения.**
  1. В `addSorToPlan` (`editorModel.ts`) оставить `objectives = sectionLast.objectives`, тему СОР сделать равной `sectionLast.lessonTopic`.
  2. Убрать из темы декоративный текст «СОР №N по разделу "…"».
- **Что решает.** Методическая преемственность: СОР за раздел оценивает материал последнего урока.
- **Метрики качества.**
  - Юнит-тест `addSorToPlan`: `lessonTopic` и `objectives` СОР равны последнему стандартному уроку раздела; в теме нет подстроки «СОР №».

### A5. Видимое обрамление таблицы по краям
- **Задача.** У таблицы не видно внешней рамки по краям.
- **Метод решения.**
  1. Задать полный `border` на контейнере таблицы в `KtpEditor.tsx`/`styles.css`.
  2. Сохранить `stickyHeader` и не сломать объединённые строки (quarter-header, плашки).
- **Что решает.** Таблица читается как цельный бланк, пригодный к печати.
- **Метрики качества.**
  - Визуально видны все 4 стороны рамки (чек-лист/скриншот).
  - Нет «рваных» границ в объединённых ячейках.

### A6. Четверть — отдельным цветом, без hover, с указанием часов
- **Задача.** Строку-заголовок четверти (`QUARTER_HEADER`) явно выделить цветом, убрать реакцию на наведение и показывать часы четверти.
- **Метод решения.**
  1. Задать отдельный фоновый цвет (`rowBackground` в `KtpEditor.tsx`), отключить hover-эффекты на этой строке.
  2. В заголовке выводить часы четверти (уже есть в `flattenPlan`: «N-я четверть · X ч/нед» — сделать явным и читаемым).
- **Что решает.** Ориентация в плане: сразу видно границы четвертей и их объём.
- **Метрики качества.**
  - На строке четверти нет hover-реакции; цвет отличен от остальных типов.
  - Часы четверти отображаются и редактируются.

### A7. Валидация часов (норма vs факт) в реальном времени
- **Задача.** Система постоянно сверяет норму часов предмета с фактическим планом и показывает ошибки в реальном времени.
- **Логика.** Дни проведения (пн/ср/пт) → 3 урока/нед; 1, 2, 4 четверти — 8 учебных недель, 3-я — 10 недель → `24 + 24 + 30 + 24 = 102`.
  - «Должно» — по четвертям: учебные недели × уроков/нед (24/24/30/24).
  - «Запланировано» — уроки четверти с проставленной датой.
  - «Фактически» — запланированные минус объединения. При празднике в четверти появляются объединения: **2 урока относятся к одной дате** (это объединение **уроков**, а не целей — уроки получают одну дату и пометку причины).
  - Итог по четвертям должен дать в сумме часы, указанные педагогом (норма, например 102). Проверка нормы: недели × уроков/нед сходится с нормой → всё верно; расходится → плашка «проверить и сверить введённые часы, распределение уроков по неделям и т.д.».
- **Метод решения.**
  1. Выделить чистый сервис `hoursValidation` (`src/ktp/`), переиспользуя логику календаря (`updateKtpSchedule`/`ktp_service.rs` и `possibleLessons` в KtpEditor): расчёт учебных дней по четвертям, «должно/запланировано/фактически», объединения (совпадающие даты).
  2. Панель сверху редактора (пересчёт при любом изменении `flat`/часов/дней).
  3. Пример вывода: «1 четв.: должно 24, запланировано 24, фактически 23 (1 объединение — 25 окт.); 2 четв.: должно 24, запланировано 20, фактически 20 — не хватает 4 уроков, 1 объединение (16 дек.)».
- **Что решает.** Соответствие нормативной нагрузке; мгновенное выявление нехватки/избытка часов и объединений.
- **Метрики качества.**
  - Контрольный расчёт `3·8·3 + 3·10 = 102` сходится.
  - Пример из замечания воспроизводится в выводе (1-я и 2-я четверти).
  - Пересчёт происходит без перезагрузки; юнит-тесты на расчёт дней, «должно/запланировано/фактически», объединений.
  - Объединение уроков = 2 урока на одну дату с пометкой причины (не слияние целей).

### A8. Хвостовые уроки повторения: тема и цель в одну строку
- **Задача.** У хвостовых уроков повторения (в конце четверти) убрать отдельную колонку целей: тема и цель — одна строка; вместо «Повторение #N» подставлять название раздела.
- **Метод решения.**
  1. Повторения в начале четверти (`repetitionInfo` в `buildKtpFromTup`/`lib.ts`) **НЕ заменяются** — остаются как есть.
  2. Хвостовые «Повторение #1/#2» заменяются на уроки по названиям разделов четверти: `max(2, sections.length)`, при одном разделе — дублировать.
  3. Разделы могут повторяться между четвертями (например, тригонометрия в 9 классе в двух четвертях с разными темами и целями) — количество разделов в четверти не нормируется, берём распределение из ТУП как есть. Разделы и уроки нельзя перемещать между четвертями (см. A2).
  4. В рендере REPETITION объединить тему и цель в одну ячейку, без отдельной колонки целей.
- **Что решает.** Повторение привязывается к реальным разделам, таблица компактнее.
- **Метрики качества.**
  - Юнит-тест: при 3 разделах в четверти — 3 хвостовые темы с названиями разделов; при 1 разделе — 2 темы (дубль).
  - Повторения из `repetitionInfo` в начале четверти не изменяются.
  - Рендер хвостового повторения в одну строку без колонки целей.

### A9. СОЧ: тема и цель в одну строку
- **Задача.** У `SOCH` тема и цель — одна строка; вместо «СОЧ» писать «Суммативное оценивание за 1/2/3/4 четверть».
- **Метод решения.**
  1. В `buildKtpFromTup`/`lib.ts` для СОЧ проставлять тему по номеру четверти (`quarter.quarterNumber`): «Суммативное оценивание за N четверть».
  2. Рендер СОЧ в одну ячейку (тема+цель), без отдельной колонки целей.
- **Что решает.** Корректное наименование контрольной работы, компактный вид.
- **Метрики качества.**
  - Текст корректный для четвертей 1–4 (тест).
  - Рендер в одну строку.

### A10. После СОР — дубликат последнего урока раздела; между СОР и СОЧ нет «повторения»
- **Задача.** После СОР должен идти дубликат последнего урока данного раздела (та же тема и цель). Между СОР и СОЧ не должно быть урока типа «повторение».
- **Метод решения.**
  1. Правило генерации: сразу после СОР вставлять дубликат последнего стандартного урока раздела (тема/цель совпадают), тип STANDARD. В `addSorToPlan` (`editorModel.ts`) дубликат уже вставляется (`hour` = копия `sectionLast`) — зафиксировать как обязательное правило и покрыть тестом.
  2. Убрать «повторение», если оно стоит между СОР и СОЧ; хвостовые повторения остаются только после СОЧ.
  3. Соблюсти инвариант FR-2.2: `Index(Soch) - Index(Last_Sor) = 2` (проверка в `domain/invariants.rs`).
- **Что решает.** Методическая дистанция СОР → СОЧ без потери учебного часа; корректная связка «раздел → СОР → дубликат → СОЧ».
- **Метрики качества.**
  - Инвариант дистанции выполняется после генерации (тест в Rust `invariants.rs`).
  - Сразу после СОР — дубликат последнего урока раздела (та же тема/цель).
  - Между СОР и СОЧ нет уроков типа REPETITION.

### A11. Объединение целей в один урок
- **Задача.** Дать возможность объединить две цели разных уроков одной темы в один урок (простая цель + простая цель).
- **Метод решения.**
  1. Доработать UX поверх `mergeObjectivesIntoLesson` (`editorModel.ts`, уже есть) и кнопки «Объединить со следующим уроком»: явное действие «объединить цели со следующим уроком этой темы».
  2. При объединении переносить цели в целевой урок, удалять исходный, пересчитывать нумерацию (`renumberPlan`).
- **Что решает.** Гибкое планирование при «лёгких» темах; не раздувает КТП лишними уроками.
- **Метрики качества.**
  - После объединения два урока одной темы → один урок с двумя целями; цели не теряются.
  - Нумерация корректна (тест).

### A12. Импорт нормативных часов («Норма часов») — отложено
- **Статус:** отложено. Облачная схема (`ktp_documents`/Supabase) будет переработана в конце, когда локально будет готово.
- **Задача (на потом).** Поле «Норма часов» в настройках КТП (например, 102 по алгебре); система постоянно сверяет план vs норма (см. A7).
- **Что решает.** Явный источник нормы для валидации часов.
- **Метрики качества (позже).**
  - Ввод 102 → сверка по четвертям работает и показывает ошибки в реальном времени.
  - Значение нормы сохраняется и восстанавливается.

## Часть B. Избранные фичи (в план)

### B1. Undo / Redo + история изменений
- **Задача.** Откат и повтор любого действия редактора (перенос, объединение, удаление, СОР/СОЧ) с лентой действий.
- **Метод решения.**
  1. В `KtpEditor.tsx` обернуть `setFlat` в обёртку истории: стеки `past`/`present`/`future` снапшотов плана (или минимальных патчей).
  2. Горячие клавиши `Ctrl+Z`/`Ctrl+Y`, панель истории (список шагов с подписью действия и таймстемпом).
  3. Кап истории (например, 100 шагов) для ограничения памяти.
- **Что решает.** Защита от случайных правок, быстрое восстановление.
- **Метрики качества.**
  - Любое действие (перенос/объединение/удаление/СОР/СОЧ) обратимо и повторимо.
  - `Ctrl+Z`/`Ctrl+Y` работают; лента показывает шаги.
  - Юнит-тест последовательности действий; снапшот плана из 300 уроков фиксируется < 50 мс.

### B2. Библиотека шаблонов КТП (клонирование на параллельный класс)
- **Задача.** Сохранить план как шаблон и клонировать на параллельный класс (7а → 7б) одной кнопкой.
- **Метод решения.**
  1. Хранилище шаблонов: SQLite-таблица (позже) / локальный файл (сейчас).
  2. Действия: «Сохранить как шаблон», «Создать из шаблона» с указанием класса.
  3. При клонировании: очищать даты и класс-специфичные поля, сбрасывать нумерацию, сохранять структуру (разделы/темы/цели/типы уроков).
- **Что решает.** Экономия времени на параллельных классах, единообразие планов.
- **Метрики качества.**
  - Клон создаёт КТП с тем же составом уроков, пустыми датами и новым классом.
  - Шаблон создаётся/удаляется/переиспользуется (тест).

### B3. Глобальное резервное копирование и восстановление
- **Задача.** Выгрузка всего, что касается пользователя (КТП, ТУП, КСП, СОР/СОЧ, настройки, календарь), в один файл и импорт на другом устройстве.
- **Метод решения.**
  1. Единый пакет-экспорт JSON с `schemaVersion` и манифестом секций (в Desktop — экспорт/импорт из SQLite).
  2. Расширяемый реестр сериализаторов: сейчас КТП + ТУП + настройки + календарь; далее добавить КСП, СОР/СОЧ без изменения формата.
  3. Импортёр с валидацией схемы, детектом конфликтов `id` и merge-стратегией (перезапись/пропуск/создать копию).
  4. Кнопки «Экспорт данных» / «Импорт данных» в настройках.
- **Что решает.** Перенос между устройствами, страховка от потери данных.
- **Метрики качества.**
  - Round-trip (экспорт → импорт) восстанавливает все данные без потерь.
  - Битые/неверные файлы отклоняются с понятной ошибкой.
  - Конфликтные `id` обрабатываются; формат версионирован (тест).

### B4. Прогресс-бар готовности
- **Задача.** Наглядная шкала по четвертям: сколько уроков заполнено, сколько осталось, % готовности.
- **Метод решения.**
  1. Селектор готовности: урок «заполнен», если заданы тема, цели и дата.
  2. Агрегация по четвертям и по плану в целом.
  3. Визуализация прогресс-баров в шапке редактора; клик по четверти → список незаполненных уроков.
- **Что решает.** Видимость полноты плана, быстрое нахождение пробелов.
- **Метрики качества.**
  - % готовности считается корректно (юнит-тест селектора).
  - Клик по четверти показывает незаполненные уроки.
