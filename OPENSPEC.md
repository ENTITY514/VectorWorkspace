# VectorWorkspace — OpenSpec Specification (v2.5)

Спецификация архитектуры, санитарных правил (СанПиН РК) и математической модели генератора школьного расписания **VectorWorkspace**.

---

## 1. Архитектурная Система (System Architecture)

### 1.1 Технологический Стек
* **Фронтенд (Desktop UI):** Tauri v2 + React 18 + TypeScript + Tailwind CSS v4 (`@tailwindcss/vite`).
* **Локальная БД:** SQLite (`vector.db` через `sqlx` в Rust).
* **Математический Движок (Solver Engine):** Python 3.13 + **Google OR-Tools CP-SAT** (Constraint Programming / Lazy Clause Generation).
* **Контракт Связи:** JSON Схема v2 (`InputModel` $\rightarrow$ `SolverOutput`).

### 1.2 Архитектура Потока Данных
```
[React / UI] ──(Tauri IPC)──> [Rust Backend (src-tauri)] ──(Pre-Validator)──> [Python OR-Tools CP-SAT]
     ▲                                   │                                            │
     └────────────────(vector.db)────────┴────────(Save Schedule JSON & DB)───────────┘
```

## 2. Санитарные Правила РК (СанПиН № ҚР ДСМ-76)

### 2.1 Шкала Трудности Предметов (Приложение 4)
* **11 баллов (Максимальная сложность):** `Математика`, `Алгебра`, `Геометрия`, `Казахский язык` (в неказ. школах), `Русский язык` (в нерус. школах).
* **10 баллов:** `Иностранный язык` (Английский).
* **9 баллов:** `Физика`, `Химия`, `Информатика`, `Биология`.
* **8 баллов:** `История`, `Основы права`.
* **7 баллов:** `Казахский/Русский язык и литература`.
* **6 баллов:** `Естествознание`, `География`.
* **5 баллов:** `Физическая культура`.
* **1–4 балла (Легкие предметы):** `Труд`, `Музыка`, `ИЗО`, `Черчение`.

### 2.2 Физиологическая Кривая Умственной Работоспособности
1. **По дням недели (Парабола нагрузки):**
   * **1–9 классы:** Пик нагрузки на **Вторник** (11) и **Четверг** (11). Среда (9) — облегченный день. Понедельник (7) и Пятница (7) — дни врабатывания и утомления.
   * **10–11 классы:** Пик нагрузки на **Вторник** и/или **Среду**.
2. **По времени дня (Почасовое правило):**
   * **2, 3 и 4 уроки (ПИК активности):** Обязательное место для предметов 9–11 баллов (`Алгебра`, `Геометрия`, `Физика`, `Химия`, `Информатика`).
   * **1-й урок:** Зона «врабатывания». Не ставить высшую сложность без необходимости.
   * **6, 7 и 8 уроки (Период глубокого утомления):** Категорический запрет на математические предметы 9–11 баллов. Назначаются предметы 1–4 баллов (`Физкультура`, `ИЗО`, `Музыка`, `Труд`).
   * **Понедельник и Пятница (вторая половина дня):** Полный запрет на математический блок на 5, 6, 7 уроках.

## 3. Математические Правила и Ограничения (CP-SAT Solver Constraints)

### 3.1 Жесткие Ограничения (Hard Constraints)
1. `H_overlap`: Запрет накладок учителей, классов и кабинетов в один слот.
2. `H_joint`: Сквозное совмещение класс-комплектов (`joint_lesson_id`) — синхронизация дня и урока для `7б` и `7б ЛУО`.
3. `H_subject_domains`: 
   * При нагрузке $\le 5$ ч/нед в 5-дневку — **строго макс 1 урок в день** по предмету в классе.
   * При нагрузке $> 5$ ч/нед — макс 2 урока в день, причем спаренные уроки идут **строго подряд без разрывов** (`подряд`).
4. `H_no_late_math`:
   * Запрет предметов математического блока (`algebra`, `geometry`, `math`) на 6-м и 7-м уроках в ЛЮБОЙ день.
   * Запрет предметов математического блока на 5-м, 6-м и 7-м уроках в Понедельник и Пятницу.
   * **Понедельник (d=0):** Математический блок стартует с **АЛГЕБРЫ** (`geometry` запрещена на Пн).
   * **Вторник (d=1):** Заступает **ГЕОМЕТРИЯ** (`algebra` запрещена на Вт).
5. `H_luo_priority`: 
   * **Нулевые окна (0 windows):** У классов ЛУО/ДО уроки образуют единый непрерывный блок.
   * **Запрет 7-го урока:** Классы ЛУО/ДО завершают занятия не позже 6-го урока.

### 3.2 Мягкие Ограничения и Штрафы (Soft Penalties)
1. `S_window`: Минимизация окон в расписании учителей.
2. `S_sanpin_parabola` & `S3b`: Штраф за отклонение суммарного дневного балла от идеальной параболы и за нарушение позиций уроков 9–11 баллов.
3. `S_alternation`: Обязательное чередование гуманитарных и естественно-математических дисциплин.
4. `S_load_balance`: Выравнивание кол-ва уроков в день по классам.

## 4. Защитный Валидатор (Rust Pre-Validator)

До вызова Python CP-SAT движка Rust производит мгновенную проверку (Pre-Validator):
1. **Дедупликация нагрузки учителей:** Сложение часов производится с учетом `joint_lesson_id` (считается реальная физическая нагрузка вместо сырой).
2. **Безопасная обработка графиков:** Если `availability_json` у учителя пуст или содержит некорректный JSON, берется матрицы вседоступности 6×8.
3. **Проверка спецкабинетов и вместимости классов.**

## 5. Запуск и Генерация

* **Быстрый тест (Draft):** 15–30 секунд (поиск допустимого расписания).
* **Стандартная генерация:** 60 секунд.
* **Глубокая оптимизация (Final Production):** 180–300 секунд (глубокое снижение окон и шлифовка СанПиН).
