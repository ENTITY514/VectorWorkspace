# Фазы: Миграция данных Q4 2026 + Расширение функционала

## Контекст

В папке `Materials/Q4 Schedule 2026/` лежат **27 XLS-файлов** — полное расписание 4-й четверти 2025-2026 учебного года. Это самые полные и корректные данные. Задача — заменить ими текущие синтетические данные и расширить функционал приложения.

- [ ] **1.5** Собрать уникальные кабинеты (спортивный зал, кабинет химии и т.д.)

- [ ] **3.4** В UI: добавить список вариантов расписания для выбранного года
- [ ] **3.5** Кнопка «Создать вариант» — копирует текущее расписание как новый вариант
- [ ] **3.6** Кнопка «Удалить вариант» — удаляет выбранный вариант (кроме основного)
- [ ] **3.7** Переключение между вариантами — загружает slots выбранного варианта
- [ ] **3.8** Генерация solver-ом создаёт новый вариант (не перезаписывает текущий)

### Вход
- Текущая схема БД

### Выход
- Миграция `0013_schedule_variants.sql`
- UI: селектор года + список вариантов
- Solver создаёт варианты вместо перезаписи

### Архитектурное решение
```
schedule_variants
├── id TEXT PRIMARY KEY
├── name TEXT NOT NULL          -- "Вариант 1", "Эксперимент"
├── academic_year TEXT NOT NULL -- "2025-2026", "2026-2027"
├── is_active BOOLEAN DEFAULT 0
├── created_at TEXT NOT NULL
└── parent_variant_id TEXT      -- FK → self (для ветвления)

schedule_slots
├── ... (существующие поля)
└── variant_id TEXT REFERENCES schedule_variants(id) ON DELETE CASCADE
```

## Порядок выполнения

```
Фаза 1 (данные) → Фаза 2 (учителя) → Фаза 3 (варианты)
                                        ↓
                              Фаза 4 (просмотр) → Фаза 5 (тестирование)
                                        ↓
                              Фаза 6 (документация)
```

Фазы 1-2 можно делать параллельно. Фаза 3 блокирует Фазу 4. Фаза 5 зависит от Фаз 1-4. Фаза 6 независима.
