# 05. Интерфейс (UI/UX) — Изолированная Вкладка «Расписание»

> Стек: React 18 + TypeScript 5 + Vite + Tauri API. Стиль: наследует `Desktop/src/styles.css` (Vector Design System). Роутер: вкладка внутри `MainLayout` (см. `Desktop/src/types.ts:View`).

## 5.1 Принцип изоляции

Вкладка «Расписание» — **отдельный домен** `Desktop/src/domains/schedule/`, не импортирующий `domains/tup`, `domains/ktp`, `panels/*`. Общение только через Tauri invoke `schedule_*`.

```
Desktop/src/domains/schedule/
├── SchedulePage.tsx          // роутер вкладки (внутренние под-вкладки)
├── api/
│   └── scheduleApi.ts        // обёртка над @tauri-apps/api/core invoke
├── types.ts                  // ScheduleState, Slot, Weights (зеркало Rust)
├── hooks/
│   ├── useScheduleState.ts
│   └── useScheduleProgress.ts // подписка на Tauri Event `schedule:progress`
├── components/
│   ├── Dashboard.tsx
│   ├── DataManagement.tsx
│   │   ├── TeachersTab.tsx
│   │   ├── ClassesTab.tsx
│   │   ├── RoomsTab.tsx
│   │   └── SubjectsTab.tsx
│   ├── CurriculumMatrix.tsx  // матрица нагрузки (самая сложная)
│   ├── ConstraintsConfigurator.tsx
│   └── TimetableGrid.tsx
└── utils/
    └── validators.ts
```

Добавление в `App.tsx`:

```typescript
export type View = "today" | "tup" | "ktp" | ... | "schedule";
// ...
{view === "schedule" && <SchedulePage />}
```

Навигация внутри `SchedulePage` — локальные табы (не `View`), чтобы не раздувать глобальный роутер.

## 5.2 Экран 1 — Dashboard (Сводка)

**Цель**: за 5 секунд понять готовность к генерации.

**Секции**:

1. **Готовность (Readiness Card)**:
   - Прогресс-бар: `Учителя 12/12 ✓ | Классы 20/20 ✓ | Кабинеты 30/35 ⚠ | Нагрузка 18/20 ✗`
   - Кнопка «Сгенерировать» — disabled пока не 100%, tooltip объясняет чего не хватает.
   - При клике — модалка «Параметры генерации» (лимит времени, seed).

2. **Статус последнего запуска**:
   - Бейдж: `OPTIMAL (23с, штраф 1230)` / `FEASIBLE (gap 3.2%)` / `INFEASIBLE` / `TIME_LIMIT`.
   - `solver_stats`: `wall_ms`, `branches`, `gap`, `penalties` разбивка.
   - Кнопка «Открыть в матрице».

3. **Список неразрешимых конфликтов** (если INFEASIBLE):
   - Красная карточка с `diagnostics.infeasible_core.reason` + список `conflicting_entities` (кликабельные ссылки на учителей/классы).
   - Кнопка «Исправить» → переход в соответствующий CRUD.

4. **Быстрые действия**: Экспорт XLSX/CSV, Очистить слоты, Демо-данные.

**Состояния**: `idle | generating (прогресс-бар + логи stderr) | done | error`.

## 5.3 Экран 2 — Data Management (Справочники)

Четыре под-вкладки внутри `DataManagement.tsx`:

### 5.3.1 Учителя (TeachersTab)

Таблица: `ФИО | BaseRoom | Max/день | Доступность | Действия`.

- **CRUD**: диалог `TeacherDialog` с полями:
  - `full_name` (text, обязателен).
  - `base_room_id` (select из `schedule_rooms`, опц.).
  - `max_daily_lessons` (number 0..10, 0=∞).
  - **Матрица доступности**: грид 6×8 чекбоксов (Пн-Сб × 1-8 урок). Кнопки «Все», «Сбросить», «Копировать Пн на все». Визуально: зелёный=доступен, серый=запрет. Приходящие учителя — отмечают только свои слоты.
- Валидация: хотя бы один `true`, иначе ошибка «Учитель никогда не доступен».
- Поиск/фильтр по ФИО.

### 5.3.2 Классы (ClassesTab)

Таблица: `Класс | Параллель | Учеников | Смена | Подгруппы | Действия`.

- Диалог: `grade` (1..11), `letter` (А-Я), `headcount` (1..50), `shift` (First/Second, radio).
- **Подгруппы**: секция «Деление» — список `subject_id → group_count (2/3)` (chips). Добавить → select из `schedule_subjects` где `requires_split` или любой язык/информатика. Удаление — с подтверждением (т.к. влияет на curriculum).

### 5.3.3 Кабинеты (RoomsTab)

Таблица: `Название | Тип | Вместимость | Закреплён | Этаж | Действия`.

- Диалог: `name` (уникально), `room_type` (select 8 типов), `capacity` (1..100), `base_teacher_id` (select учителя), `floor` (1..5, опц.).
- Фильтр по `room_type` (чипсы: Все / Химия / Информатика / Спортзал...).
- Индикатор: если `capacity < headcount` какого-то класса — жёлтое предупреждение (но не Hard, т.к. вместимость — Soft в MVP, Hard — опционально).

### 5.3.4 Предметы (SubjectsTab)

Таблица: `Предмет | Вес СанПиН | Спецкабинет | Делится | Сдвоенные | Родственные | Действия`.

- Диалог: `name`, `sanitary_weight` (1..10, слайдер + число, цвет: 1-3 зелёный, 4-7 жёлтый, 8-10 красный), `required_room_type` (select, null=любой), `requires_split` (toggle), `is_double_allowed` (toggle), `related_subject_ids` (multi-select).
- Подсказка: веса по умолчанию из СанПиН (матем 9, физ-ра 2...) — кнопка «Сбросить к СанПиН».

### 5.3.5 Общие UX-правила справочников

- Все таблицы — виртуализированы (react-virtuoso) при >100 строк.
- Поиск debounce 300мс, фильтр по типу.
- Удаление — soft-delete с confirm (т.к. есть FK в curriculum/slots).
- Toast-уведомления на успех/ошибку (Tauri `message`).

## 5.4 Экран 3 — Curriculum Matrix (Матрица Нагрузки)

**Самый сложный UI-блок** — связка `Класс × Предмет → Учитель + Часы`.

**Макет**: таблица где строки — классы (8А, 8Б...), столбцы — предметы (Алгебра, Геометрия...), ячейка — `Учитель (+часы)` или `—`.

- **Ячейка**: если `hours_per_week >0` — чип `Иванов И.И. · 3ч` (цвет по учителю), иначе `+` (добавить). Для `requires_split` — два чипа `Петрова / Сидорова · 3ч`.
- **Редактирование**: клик → поповер `CurriculumCellEditor`:
  - `teacher_id` (select, фильтр по предмету — опционально).
  - Для split: два селекта `teacher1`, `teacher2` (не могут совпадать).
  - `hours_per_week` (1..6, stepper).
  - Кнопки Сохранить / Удалить (обнулить).
- **Валидация**:
  - Часы сверяются с ТУП (если `hours_per_week` > `tup.hours` — предупреждение).
  - У учителя сумма часов по всем классам не должна превышать `availability` слотов — жёлтое предупреждение (Hard проверит солвер).
- **Действия**: «Заполнить из ТУП» (автозаполнение часов по умолчанию), «Очистить», «Демо-нагрузка».

**Производительность**: матрица 30×15=450 ячеек — рендерится без виртуализации, но с `React.memo` на ячейку.

## 5.5 Экран 4 — Constraints Configurator (Веса Soft)

**Цель**: дать завучу «ползунки» для управления параболой/окнами без пересборки.

**Макет**: список карточек-слайдеров:

| Ползунок | Диапазон | Дефолт | Описание | Эффект 0 |
|----------|----------|--------|----------|----------|
| Окна учителей | 0..1000 | 200 | Штраф за пустой слот между уроками | Окна игнорируются |
| Изгнание из кабинета | 0..1000 | 50 | Штраф если не в BaseRoom | Все кабинеты равны |
| СанПиН-парабола | 0..1000 | 100 | Отклонение от идеальной параболы | Пик Вт-Ср не важен |
| Чередование | 0..1000 | 80 | Алгебра/геометрия не в один день | Можно в один день |
| Миграция | 0..1000 | 20 | Переходы между этажами | Игнорируется |
| Баланс нагрузки | 0..1000 | 30 | Дисперсия уроков/день | Дни могут быть 1/8 |

- Каждый слайдер — `input[type=range]` + числовое поле + бейдж «Отключено» при 0.
- Кнопки: «Сбросить к дефолту», «Сохранить» (invoke `schedule_set_weights`), «Сгенерировать с этими весами».
- Подсказка: «Вес 0 мгновенно отключает ограничение — пересборка модели не требуется, только objective».

## 5.6 Экран 5 — Timetable Grid (Матрица Расписания)

**Интерактивная таблица** — сердце вкладки.

### 5.6.1 Режимы просмотра

Переключатель: `По классам | По учителям | По кабинетам`.

- **По классам**: строки — периоды (1-8), столбцы — дни (Пн-Сб), ячейка — урок `Предмет · Учитель · Кабинет`. Фильтр сверху: select класса (8А).
- **По учителям**: аналогично, ячейка — `Класс · Предмет · Кабинет`, фильтр учителя.
- **По кабинетам**: ячейка — `Класс · Предмет · Учитель`, фильтр кабинета.

### 5.6.2 Визуализация

- **Цвета**: предмет → цвет (палитра 12 цветов, детерминирована по `subject_id`).
- **Подгруппы**: ячейка делится диагональю на 2 (1гр/2гр) с разными учителями/кабинетами, но один `T`.
- **Окна**: пустая ячейка между уроками учителя — жёлтая штриховка + tooltip «Окно».
- **Коллизии**: Hard-нарушение — красная рамка (в норме не бывает; показывается только при ручном редактировании если разрешим).
- **СанПиН**: внизу грида — график «Сумма весов по дням vs парабола» (Recharts Line), подсветка дней с превышением.

### 5.6.3 Фильтры и действия

- Фильтры: класс/учитель/кабинет (зависит от режима), день (чипсы Пн-Сб), поиск по предмету.
- Действия: «Экспорт XLSX» (по классам/учителям), «Печать», «Копировать слот» (drag-and-drop — в V2, в MVP только просмотр).
- Пустые слоты — серые, занятые — цветные чипсы.

### 5.6.4 Состояния

- `empty` — «Расписание ещё не сгенерировано» + кнопка «Сгенерировать».
- `loading` — скелетон грида.
- `infeasible` — не грид, а карточка конфликта (см. Dashboard).
- `done` — грид + бейдж `OPTIMAL` + разбивка штрафов (мини-диаграмма).

## 5.8 Дизайн-токены (наследуются)

- Цвета: `var(--bg)`, `var(--card)`, `var(--accent)` из `styles.css`.
- Компоненты: `Card`, `Button`, `Dialog`, `Select` из `shared/ui`.
- Иконки: `lucide-react` (уже в `Desktop/package.json`).

## 5.9 Адаптивность и доступность

- Грид — горизонтальный скролл на малых экранах, sticky-заголовки дней.
- Клавиатура: `Tab` по ячейкам, `Enter` → редактор curriculum, `Esc` → закрыть.
- `aria-label` на каждой ячейке: «Понедельник 3 урок, Алгебра, Иванов, каб 12».

## 5.10 Чек-лист UI-готовности

- [ ] Все 5 экранов рендерятся без `schedule_*` данных (empty-state).
- [ ] Матрица доступности 6×8 — кликабельна, состояние сохраняется.
- [ ] Ползунки весов: 0 отключает, 1000 — максимум, сохраняется в SQLite.
- [ ] Грид переключает режимы без перезагрузки, фильтры работают.
- [ ] INFEASIBLE-карточка показывает кликабельные сущности.
- [ ] Линт `no-restricted-imports` не пропускает `tup` в `schedule`.
