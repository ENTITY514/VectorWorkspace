# Стандарты и принципы кода

## Общие правила

1. **Читаемость > микрооптимизации**, пока нет измерения.
2. **Маленькие файлы**, особенно React-компоненты.
3. **Разделяй**: отображение / логика (hooks, use-cases) / данные (repositories) / типы.
4. **Не раздувай page.tsx** — страница только компонует виджеты и фичи.
5. **Не тащи `supabase-js` в UI-компоненты** — только через repository.
6. **Секреты** только в корневом `.env.local`.
7. **Имена** — понятные, по домену (`TupCatalog`, не `DataThing`).
8. Комментарии — только где неочевидный инвариант; не narrate код.

## TypeScript

- Явные типы на границах модулей (props, repository contracts, DB mappers).
- Не использовать `any` без крайней нужды; если нужно — локально и с причиной.
- Mapper `row → domain` держать рядом с адаптером (`mappers.ts`).

## Ошибки и UX

- Репозиторий бросает Error / пробрасывает supabase error.
- Feature-hook ловит и кладёт `error: string | null` для Alert.
- Не глотать ошибки пустым `catch {}` без причины.

## Тесты

- Парсеры и чистые преобразования — unit-тесты рядом (`*.test.tsx` / `*.test.ts`).
- UI e2e — позже (Playwright), не блокирует текущий FSD.

## Git / PR

- Не коммитить `.env.local`, `node_modules`, `build`.
- Коммиты осмысленные; крупные фичи — отдельными логическими коммитами по возможности.
- Документацию в `/docs` обновлять вместе с изменением контрактов/схемы.
