# 13. Дорожная карта реализации (10 фаз)

> План ковки Vector по крупным фазам. Каждая фаза — большой пласт работы с жёсткими
> критериями приёмки: фаза считается завершённой только после прохождения тестов.
> Версия: 1.0 · Статус: утверждено.

## Фаза 1 — Фундамент ядра (смена подвала)

- Выкорчевать `rusqlite` и старую упрощённую схему.
- Поднять `tokio` + `sqlx::SqlitePool` (WAL, `foreign_keys=ON`).
- Применить полный production DDL (doc 09) + школьные таблицы (doc 12 §IX) как версионированные миграции `sqlx::migrate!`.
- Каркас слоёв `commands/ → domain/ → db/ → infra/` + Health-команда.

**Проверяем:** миграции накатываются «с нуля» и повторно; `cargo test` зелёный; приложение стартует с пустой БД.

## Фаза 2 — Идентичность (школа, штат, профиль, классы)

- Репозитории + CRUD: `schools`, `school_staff` (is_active, valid_from/valid_to), `teacher_profiles`, `classes`.
- Экран «Настройки школы» + онбординг при первом запуске.

**Проверяем:** temporal integrity — смена директора не переписывает старые подписи; constraint'ы (grade 1–12, language RU/KK).

## Фаза 3 — Нормативный базис (ТУП → БД)

- Парсер `.xlsx` из `Materials` (7–9 и 10 кл., объединения/часы).
- Детект маркеров дисциплин, рассечение алгебры и геометрии на независимые `TupDocument` (subject × grade).
- Код цели `[класс].[раздел].[подраздел].[номер]`, дедупликация, валидация.
- UI загрузки/просмотра ТУП.

**Проверяем:** парсер без сбоев проходит реальные файлы `Materials` (в т.ч. неровные строки Excel); в БД чистота — ни одного смешанного предмета.

## Фаза 4 — Календарь РК + генерация КТП

- Локальная таблица производственного календаря (импорт JSON-пакета раз в год, offline-first).
- FR-3.3 адаптивный календарный сдвиг; даты авто + ручное редактирование каждого урока.
- Генерация КТП из ТУП, инварианты FR-2.2/FR-2.4.
- UI: редактор КТП по иерархии `features/` (Таблица→Строка→Ячейка).

**Проверяем:** инварианты оценивания (буфер = 1 урок от последнего СОР), сдвиг дат при праздниках/переносах, часы в неделю.

## Фаза 5 — КСП (каркас + хронометраж)

- Структура по 130 приказу: этапы, цели обучения, воспитательный компонент.
- Эталон длительности урока (45/40 мин), инвариант `Σ == эталон` точно.
- Экспорт docx.

**Проверяем:** хронометраж сходится без диапазонов; каркас генерируется из урока корректно.

## Фаза 6 — СОР/СОЧ

- Спецификации, шаблоны заданий, изоморфизм вариантов, дескрипторы, двойной баланс баллов, диагностика.
- Экспорт.

**Проверяем:** изоморфизм (одинаковые критерии, разные числа), сумма баллов по спецификации, диагностика соответствия ЦО.

## Фаза 7 — База знаний (индексатор учебников)

- Гибридный PDF-пайплайн: текстовый слой + фоновый OCR для сканов; конверсия математики в LaTeX.
- Иерархия книга→параграф→задание.
- Индексация из любой указанной папки (без хардкод-путей).
- FTS5 + эмбеддинги.

**Проверяем:** индексация реальных PDF, поиск по заданию, устойчивость к скан-страницам.

## Фаза 8 — AI/MCP-ядро

- Встроенный MCP (JSON-RPC 2.0): Transport (stdio + входящие), Tool Registry, Context Reducer (3-Point, dense markdown), Provider Gateway (Circuit Breaker, Fallback, OS Keyring), Staging Quarantine.
- Полноэкранный DiffViewer.

**Проверяем:** JSON-RPC контракты, карантин отклоняет нарушение инвариантов, circuit breaker переключает провайдера.

## Фаза 9 — Сквозная генерация КСП с ИИ

- Полный контур: React → invoke → 3-Point контекст → OpenCode (spawn/kill через stdio) → Quarantine → DiffViewer → подтверждение → атомарный commit в SQLite.
- Подбор заданий из базы знаний по коду цели.

**Проверяем:** E2E-сценарий «сгенерировал → увидел дифф → подтвердил → КСП в БД», зависший агент убивается и перезапускается.

## Фаза 10 — Материализация и бета-релиз

- Движок материализации: полные титульники с подписями (директор/завуч/МО, ревизия подписи), все экспорты (Word/XLSX/Kundelik).
- i18n-архитектура (RU активен, KK = один JSON).
- Аналитика, пакет обновления календаря. Сборка (NSIS).

**Проверяем:** полный цикл учителя 8–10 кл. без перенабора данных; документы идентичны при повторном открытии архива (застывшая история).
