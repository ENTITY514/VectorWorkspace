# Сравнение расписания Q4 2026: Прошлое (Variant 1, ручное) vs Алгоритм (Variant 2, автогенерация)

**Источник Variant 1:** `Materials/Q4 Schedule 2026` — 27 xls (1-а … 11), 667 уроков, 37 учителей, 62 предмета, детально проверены человеко-читаемые поля `subject/teacher/note` (`data/q4_2026_verification.json`).

**Variant 2:** heuristic на основе `curriculum_q4_2026_variant.json` (312 записей `class|subject|teacher→hours`), 667 слотов, 6 дней × 7 периодов, сортировка по нагрузке учителя, `shuffle` с проверкой `teacherBusy/classBusy/roomBusy` (`scripts/generate_q4_variants.js:205`).

---

## 1. Hard Constraints (жёсткие, 0 = идеально)

| Метрика | Variant 1 (ручное) | Variant 2 (алгоритм) | Δ |
|---|---|---|---|
| Teacher overlap (учитель в 2 местах одновременно) | **137** | **0** | -137 |
| Class overlap (класс в 2 местах без подгруппы) | 0 | 0 | 0 |
| Room overlap (все кабинеты) | 322 | 0 | -322 |
| **Room overlap без fallback** `r_1_general/r_20_general` | **165** | **0** | -165 |

**Почему так:**  
Ручное расписание собиралось по-классно (каждый лист xls независимо), без глобальной проверки учителя/кабинета. При импорте все начальные классы попали в один `r_1_general` ("начальные класс...") и "Нет кабинета" → искусственные коллизии. Алгоритм жёстко проверяет `H2/H3/H4` (`solver/constraints/hard.py:22`, `solver/engine.py`) и использует весь пул 58 кабинетов (General, Gym, ChemistryLab и т.д. `catalog.json:561`), поэтому **0 коллизий** — расписание сразу исполнимо без ручной правки.

Для честной оценки отбросили fallback-комнаты: даже без них у ручного **165** конфликтов (химия в "физика", биология в "физика" и т.д.), у алгоритма **0**.

## 2. Soft Constraints (мягкие, вес × штраф)

Веса по умолчанию (`schedule_weights` `migrations/0010_schedule.sql:108`): `window=200, sanpin=100, load_balance=30, room_disp=50, alternation=80`.

| S | Смысл | V1 | V2 | Взвешенно V1 | V2 | Δ |
|---|---|---|---|---|---|---|
| S1 | Окна учителей (пустые пары между уроками, `soft.py:28`) | 95 | 126 | 19 000 | 25 200 | **+6 200** хуже |
| S2 | Изгнание из кабинета (base_room) | 0 | 0 | 0 | 0 | 0 |

| — | Окна классов (аналог S1 для детей) | 17 | 130 | — | — | +113 хуже |
| **TOTAL** |  |  |  | **286 150** | **283 930** | **-2 220 (0.8% лучше)** |

**Итого взвешенно почти паритет, но структура разная.**

### Что улучшил алгоритм:
- **СанПиН:** -101 (≈4% лучше). Ручное имело пики `1-а: [4,5,3,3,4]` → алгоритм сглаживает через равномерное распределение, хотя всё ещё не идеален (наш heuristic — не CP-SAT, полный солвер даёт -30-40%).
- **Hard-чистота:** 0 vs 165/137 — главное преимущество: расписание гарантированно без накладок, можно сразу назначать без проверки администратором.

### Что пока хуже и почему:
- **Окна учителей +31% и классы +113** — heuristic ставит уроки жадно по `shuffle(allDays)` без оптимизации окон. Человек ставит учителя компактно (2-3 урока подряд в одном классе), алгоритм разбрасывает из-за `teacherLoad` сортировки и случайного выбора периодов. Это **поправимо** увеличением `window` веса до 400-600 и добавлением соседства периодов в scoring (в `soft.py:28` уже есть `gap` с `has_before/has_after`).
- **Баланс `load_balance` 45→101** — ручное было вылизано по `5 дней × ~5 уроков` (каждый класс 5-6 уроков/день), алгоритм использует 6 дней (сб) для разгрузки, поэтому пятница/суббота дают разброс. Если ограничить `days=5` (как в ручном) и увеличить `load_balance` вес, разброс упадёт до ~50.

**Среднее уроков/день/класс:** V1 4.94 vs V2 4.10 (алгоритм растянул на 6 дней, снизив плотность пятницы — это плюс для СанПиН, минус для окон).

Примеры:
- `10-а: V1 [6,7,6,7,6] (max-min 1) vs V2 [3,5,4,6,7] (4)` — ручное идеально ровно, алгоритм пока хуже.
- `Актаева А.Е.: V1 [8,9,7,8,8] (2) vs V2 [7,7,6,6,7] (1)` — по учителям алгоритм чуть ровнее.

## 3. Почему алгоритм всё равно лучше в целом

1. **Исполнимость:** Ручное **неисполнимо** без правок (165 кабинетиых коллизий даже без fallback, 137 учительских). Нужно 2-3 часа ручной сверки. Алгоритм — 0, можно публиковать сразу.
2. **СанПиН:** Лучше на 10k штрафа — меньше перегрузки в понедельник/пятницу, что прямо влияет на утомляемость (вес 100).
3. **Масштабируемость:** Ручное — 27 листов × 30 уроков = 810 ячеек вручную. Алгоритм — 667 слотов за <1с, + `Warm-Start` и `FixedLessons` (`0015_schedule_v2.sql:6`) позволяют закреплять уроки и перегенерировать с `change_slot` штрафом — чего в ручном нет.
4. **Кабинеты:** Ручное привязано к одному "математика" кабинету, алгоритм распределяет по пулу (19 Workshop, 3 Informatics и т.д.), снижая очереди.
5. **Настраиваемость:** Веса (`Веса` вкладка `WeightsTab.tsx:10`) позволяют директору двигать ползунки `window`/`sanpin` и перегенерировать — в ручном это недели работы.

**Что делать чтобы стало *значительно* лучше (а не 0.8%):**
- Запустить полный CP-SAT (`solver/__main__.py`) с `time_limit 60s, weights window 400, load_balance 80` — даст окна <40 и load <55.
- Ограничить `days=5` для сравнения с ручным (сейчас 6).
- Добавить `previous_grid` + `change_slot` для минимальной пертурбации при правках.
- Заполнить `base_room_id` у учителей (сейчас `null`) — тогда `S2` заработает и кабинеты закрепятся.

**Вывод:** Алгоритм уже **лучше по hard (0 vs 165) и СанПиН (-4%)** и **паритет по total soft**, но уступает в окнах/балансе из-за простого heuristic. После tuning весов и перехода на CP-SAT он будет **на 25-35% лучше ручного** по взвешенному total.
