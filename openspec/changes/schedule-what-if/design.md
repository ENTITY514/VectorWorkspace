# Design: «Что если» и объяснение невыполнимости

## Пробный расчёт («Оценить цену»)

- Создаётся временный вариант (`kind='sandbox'`, скрыт из списка, удаляется через 7 дней или при отказе).
- Выполняется доработка (этап 1 + короткий этап 2, по умолчанию 3 + 7 мин) от текущей версии с изменением.
- Метрики — единой функцией (`solver/metrics.py`), базой служит текущая версия.

### Карточка цены

```
┌ Цена: «Маленькие классы — большой зал (почти обязательно)» ────────────────────┐
│ Сдвинуто уроков: 7 (затронуто: 5А, 6А, 8Ә, 11А; Кашиков, Ольков, Досаева)       │
│ СанПиН  1127 → 1141  ▲ +14 (хуже)                                              │
│ Окна    84 → 84      Сдвоенные 17 → 15 ▼   Дни ради 1 урока 5 → 7 ▲           │
│ Цель достигнута частично: 3 из 6 уроков в большом зале                          │
│   Причина для остальных: Ср 6 и Пт 5 — в большом зале закреплённые 3А и 4Б      │
│ [Показать изменения]   [Применить как новую версию]   [Отказаться]              │
└──────────────────────────────────────────────────────────────────────────────────┘
```

Строка «Цель достигнута частично» появляется, когда мягкое целевое правило выполнено не полностью; причина берётся
из анализа занятости (см. ниже).

### Сравнение сценариев

`ScenarioCompare` — до 4 пробных расчётов в колонках: одинаковые строки метрик, подсветка лучшего; кнопка
«Применить» у каждого. Типовые наборы: «Обязательно vs По возможности», «Уровень Важно vs Критично»,
«Бюджет 10 vs 30 минут».

## Быстрая проверка выполнимости

- Режим «только допустимость» (без цели) с подсказкой — текущая версия; лимит 60 с.
- Ответ: «Выполнимо» / «Не удалось проверить за 60 с (вероятно выполнимо)» / «Невыполнимо → объяснение».
- Запускается автоматически при переводе правила в «Обязательно» и перед расчётом дольше 10 минут.
- Важно: «не нашли за 60 с» ≠ «невыполнимо». В кейсе проверки без подсказки давали UNKNOWN на выполнимых задачах.

## Объяснение невыполнимости

### Шаг 1. Предпроверки ёмкости (миллисекунды)

| Проверка | Пример сообщения |
|---|---|
| Рабочие дни учителя | «Мельников: нужно 3 дня по 3 урока в уроки 1–5; доступно 5 дней — ок» |
| Большой зал по дням | «Пт, уроки 1–5: большой зал свободен только на 1-м уроке (2-й — 1А/1Б, 3-й — 3А, 4-й — 2Б, 5-й — 4Б). Нужно: 9Б и 10А (большие классы) у Мельникова в Пт» |
| Учитель и закрепления | «Пт 1: у 9Б закреплена алгебра (Бабич) — 9Б не может быть на физкультуре в 1-й урок» |
| Часы класса | «7А: 32 урока при лимите 7 × 5 = 35 — ок» |
| Ученик на инклюзии | «7А: 9 непосещаемых уроков; с правилом “с 1-го урока, до 6-го” их можно поставить только в 6–7 уроки или окна (≤ 3) — нужно ≥ 6 мест, есть 7 — ок» |

### Шаг 2. Минимальный конфликт (секунды–минуты)

- Каждая **группа** обязательных требований получает литерал-предположение: правило каталога × область
  (учитель/класс/день), закрепления по причине, профиль (режим работы учителя, ученик на инклюзии, залы).
- CP-SAT с `assumptions` → `SufficientAssumptionsForInfeasibility`; затем удаление лишних (deletion-based
  minimization) до минимального набора. Лимит — 2 минуты; при превышении показывается лучший найденный набор.
- Пример из кейса: {«Мельников: 3 дня по 3 урока, уроки 1–5», «Мельников: два окна подряд запрещены»,
  «Большой класс — большой зал», «Закреплённая сетка началки»} — снятие любого делает задачу выполнимой.

### Шаг 3. Текст и варианты ослабления

```
┌ Невозможно выполнить все обязательные требования ─────────────────────────────┐
│ Мельников (директор, физкультура 9Б, 10А, 11Б) должен работать 3 дня по 3 урока │
│ на уроках 1–5 без двух окон подряд. Во вторник и четверг это возможно, но третий│
│ день — Пн, Ср или Пт — упирается в большой зал: на уроках 1–5 он занят началкой │
│ (закреплённая сетка завучей), и 9Б/10А туда не помещаются без двух окон подряд.  │
│                                                                                 │
│ Варианты:                                                     цена              │
│  ○ Два окна подряд у Мельникова — большой штраф, не запрет   оценить ▸          │
│  ○ 10А (12 уч.) в пятницу — в малый зал                        оценить ▸          │
│  ○ Сдвинуть один урок физкультуры началки в пятницу            оценить ▸          │
│  ○ Разрешить Мельникову 6-й урок в пятницу                     оценить ▸          │
└─────────────────────────────────────────────────────────────────────────────────┘
```

- Варианты ослабления генерируются из групп в минимальном конфликте: «перевести в По возможности», «снять для
  конкретной сущности/дня», «расширить параметр» (уроки 1–5 → 1–6), «снять закрепление».
- «Оценить ▸» запускает пробный расчёт с этим ослаблением.

## Риски

- Минимальный конфликт на большой модели может не найтись за лимит → показываем предпроверки и неполный набор
  с пометкой.
- Тексты объяснений — шаблоны на группу правил; новые правила обязаны иметь шаблон (проверяется тестом реестра).
