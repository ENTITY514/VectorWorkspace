# Design: Профиль школы — роли и особые ограничения

## Context

Источник требований — доработка реального расписания (см. `docs/schedule/06-lessons-v33-v53.md`).
Все правила ниже уже реализованы и проверены в исследовательском солвере `tools/bilimclass/schedule/model.py`
(поля `Profile`: `teacher_days_exact`, `start_first_teachers`, `luo_student_*`, `gym_hard_classes`,
`alternate_groups`, `babich_*`, `single_lesson_day`, `low_load_*`, …). Задача — перенести их в продукт
как **данные школы**, а не как константы скрипта.

## Goals / Non-Goals

**Goals**
- Любое требование из реального кейса выражается через UI без правки кода.
- Профиль один на школу и год; переиспользуется всеми вариантами расписания.
- Солвер получает профиль в контракте и обязан его учитывать; проверка (`verify`) проверяет те же правила.

**Non-Goals**
- Выбор жёсткости и приоритета правила (→ `schedule-rules-priorities`).
- Автоимпорт профиля из BilimClass (позже; сейчас — ручной ввод и импорт из JSON исследовательского контура).

## Модель данных

### 1. Режим работы учителя — `schedule_teacher_profile`

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `teacher_id` | TEXT PK FK | — | учитель |
| `employment` | TEXT `staff`/`part_time`/`admin` | `staff` | совместитель — сниженная цена окон; администрация — ограниченные дни |
| `arrives_first_lesson` | INTEGER 0/1/NULL | NULL = авто | NULL → берётся из роли «классный руководитель» |
| `work_days_mode` | TEXT `any`/`exact`/`max` | `any` | |
| `work_days_count` | INTEGER 1..6 | NULL | для `exact`/`max` |
| `lessons_per_day_min` | INTEGER 0..8 | 0 | 2 = «не приходит ради одного урока» (жёсткая форма) |
| `lessons_per_day_max` | INTEGER 0..8 | 0 | 0 = без предела; для `exact`-дней — ровно |
| `first_period` / `last_period` | INTEGER 1..9 | 1 / NULL | «только 1–5 уроки» |
| `weekly_window_cap` | INTEGER | NULL | жёсткий предел окон в неделю |
| `no_double_window` | INTEGER 0/1 | 0 | два окна подряд — запрещены |
| `avoid_single_lesson_day` | INTEGER 0/1 | 1 | мягкая форма «ради одного урока» |
| `note` | TEXT | '' | причина (показывается в отчётах) |

Совместимость: матрица `availability_json` остаётся источником «когда учитель физически может»;
профиль описывает «как он хочет/должен работать». Противоречия (например, `exact 3` при двух доступных днях)
показывает чек-лист.

**Классный руководитель** — вычисляемое: `schedule_classes.class_teacher_id` (добавить колонку, если нет;
заполняется из BilimClass). Флаг школы `settings.class_teachers_arrive_first` (по умолчанию 1) включает
`arrives_first_lesson` для всех классных руководителей, у кого поле NULL.

Семантика `arrives_first_lesson`: окно считается от 1-го урока — `window = last + 1 − lessons` вместо
`last − first + 1 − lessons`. Дополнительно может стать жёстким «в каждый рабочий день урок на 1-м уроке»
(жёсткость — в каталоге правил).

### 2. Ученики на инклюзии — `schedule_inclusion_students`, `schedule_inclusion_attendance`

```
schedule_inclusion_students(
  id TEXT PK, display_name TEXT, class_id FK, program TEXT ('ЛУО','ЗПР',…),
  arrives_first_lesson INTEGER DEFAULT 1,  -- СанПиН: дети приходят вместе с классом
  last_period_max INTEGER NULL,            -- уходит не позже урока K
  last_period_soft INTEGER NULL,           -- урок, начиная с которого «нежелательно» (штраф)
  windows_per_day_max INTEGER NULL, windows_per_week_max INTEGER NULL
)
schedule_inclusion_attendance(
  student_id FK, subject_id FK,            -- предмет класса
  attends_hours INTEGER,                   -- = часам класса → ходит на все; < → солвер выбирает какие
  note TEXT
)
```

Окно ученика — урок класса, на котором ученика нет, между его уроками. Выбор «какие N из M уроков
посещает» делает солвер (переменные выбора), результат сохраняется в слотах (`attending_students_json`),
чтобы бланк ЛУО показывал точный маршрут.

### 3. Залы по размеру — `schedule_rooms.hall_size`, `schedule_classes.hall_size_override`

- `hall_size ∈ {big, small, NULL}` для комнат типа `Gym`.
- Категория класса: `headcount > settings.small_hall_max_headcount` → `big`, иначе `small`
  (для класс-комплекта — сумма численностей).
- `hall_size_override` + `hall_size_override_days_json` — исключения «можно в малый зал в пятницу»
  (решение школы, с причиной).
- Правило: большой класс — только большой зал; маленький — любой, «по возможности большой» (приоритет в
  каталоге правил). Постобработка кабинетов перекладывает маленький класс в большой зал, если тот свободен.

### 4. Парные предметы — `schedule_subject_pairs`

```
schedule_subject_pairs(id, name, kind TEXT ('alternate','chain'), subject_ids_json, classes_scope_json NULL)
```

- `alternate`: между двумя уроками предмета A по неделе стоит урок другого предмета группы.
- `chain`: строгий шаблон (всемирная история — между двумя уроками истории Казахстана).
- Неизбежные повторы (часы 4 + 1, сдвоенный урок) рассчитываются и в отчёте не считаются нарушением.

### 5. Обмены кабинетами — `schedule_room_swaps`

```
schedule_room_swaps(id, owner_teacher_id, owner_room_id, guest_subject_id, guest_teacher_id,
                    fallback_room_id, excluded_class_ids_json, cheaper_subject_ids_json, weekly_cap INTEGER NULL)
```

Пример: владелец каб. 17 (математика) уходит в каб. 19 только на время химии; в 10А — никогда;
на геометрии во Вт/Чт — дешевле; не больше N раз в неделю. Метрика «обменов» выводится в сводке всегда.

### 6. Пожелания учителей — `schedule_teacher_wishes`

```
schedule_teacher_wishes(id, teacher_id, rule_code TEXT, scope_json, effect TEXT ('exempt','prefer','avoid'),
                        reason TEXT, author TEXT, created_at)
```

`exempt` снимает правило каталога для указанного класса/предмета (пример: чередование каз. языка и
литературы в 8Ә). Пожелание видно в отчёте рядом с «нарушением», чтобы его не «чинили».

```json

                 "work_days": {"mode": "exact", "count": 3}, "lessons_per_day": {"min": 3, "max": 3},
                 "periods": {"first": 1, "last": 5}, "weekly_window_cap": null,

  "inclusion_students": [{ "id": "s1", "class_id": "7a", "arrives_first_lesson": true,

  "halls": { "small_hall_max_headcount": 8, "rooms": {"gym01": "big", "gym02": "small"},
```

## UI

### «Профиль школы» — мастер (новая под-вкладка перед «Генерацией»)

```
┌ Профиль школы 2026–2027 ──────────────────────────── готовность 78 % ┐
│ ✅ Сетка и смены         ✅ Кабинеты и залы        ⚠ Учителя (3)     │
│ ✅ Классы и численность  ⚠ Инклюзия (1)            ○ Парные предметы │
│ ○ Обмены кабинетами      ○ Пожелания                                 │
├──────────────────────────────────────────────────────────────────────┤
│ ⚠ Классный руководитель 11Б: в доступности нет 1-го урока во Вт      │
│ ⚠ Директор: «ровно 3 дня», но большой зал в Пн/Ср/Пт занят 1–5 уроки │
│ ⚠ 10А (12 уч.) > малый зал (8) — назначен только большой зал        │
└──────────────────────────────────────────────────────────────────────┘
```

- Каждый раздел — отдельный шаг с таблицей и быстрыми пресетами.
- Предупреждения кликабельны → открывают нужную карточку.
- Готовность = доля разделов без ошибок; генерация при ошибках разрешена, но с баннером.

### Карточка учителя (`TeacherDrawer`) — секция «Режим работы»

- Переключатель роли: Штатный / Совместитель / Администрация.
- «Приходит к 1-му уроку»: Авто (классный руководитель 8Б) / Да / Нет.
- Рабочие дни: Любые / Ровно [3] / Не больше [ ]; уроков в день: от [ ] до [ ]; уроки с [1] по [5].
- Окна: предел в неделю [ ]; ☐ два окна подряд запрещены; ☑ не ставить день ради одного урока.
- Причина / комментарий (обязателен для администрации и исключений).
- Справа — мини-превью недели из активного варианта с подсветкой нарушений профиля.

### Вкладка «Инклюзия»

Таблица учеников → карточка: класс, программа, список предметов класса с «посещает: все / N из M / нет»,
правила дня. Превью: неделя класса с отметками ✔/— и окнами ученика.

### Парные предметы, обмены кабинетами, пожелания

Простые списки с пресетами («Типовые пары для 5–11 классов», «Химия ↔ кабинет математики»).

## Решения и альтернативы

- **Профиль отдельно от доступности.** Альтернатива — кодировать всё в матрице 6×8 (как делали для
  директора) — теряет смысл («ровно 3 любых дня» не выражается матрицей) и ломает оптимизацию.
- **Классный руководитель — вычисляемая роль.** Школа меняет классных руководителей; правило должно
  следовать автоматически.
- **Выбор посещаемых уроков делает солвер.** Ручной выбор часто делает задачу хуже (в кейсе выбор
  «какие 2 из 4 казахских» снизил окна ученицы с 2 до 0).

## Risks

- Рост модели (переменные выбора посещения, окна учеников) → +время решения. Смягчение: двухэтапный расчёт
  (см. `schedule-revision-mode`), ученики на инклюзии — обычно единицы.
- Противоречивый профиль → INFEASIBLE. Смягчение: чек-лист + объяснение невыполнимости (`schedule-what-if`).
