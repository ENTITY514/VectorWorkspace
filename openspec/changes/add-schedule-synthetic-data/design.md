## Context

Система расписания (`schedule_*`, `engine.py` CP-SAT, 6 Soft) готова и прошла 104 Rust + 19 Python теста. Данных нет: `schedule_teachers/rooms/classes/curriculum` пусты, проверить `≤60с` и сравнить с ручной работой не на чем. В `Materials/Таблицы расписаний` 115 OLE `.xls` (строки 0 `Класс: 1-а[ ДО| ЛУО]`, 1 `N четверть`, 2-3 заголовки `пн..пт`+даты, 4+ ячейки `Предмет\nФИО\nВремя\nКабинет` на 5 дней×7 периодов, 8 недель на четверть). Первая неделя часто неполная (1 сент — пусто, праздник). С 2-й по 8-ю — стабильный недельный шаблон. ДО/ЛУО — отдельные типы (≤15 кл), нельзя смешивать в одном `time_grid`. Комнаты в ячейках не нормализованы (`начальные класс…`→`General`). Нужен читаемый JSON (не SQLite) для программной проверки и UI.

## Goals / Non-Goals

**Goals:**
- За 1 команду получить `catalog.json` (все учителя/классы/комнаты/предметы с весами СанПиН) + 4× `curriculum_qN.json` + 4× `schedule_legacy_qN.json` (недельный 5×7, первая полная неделя каждой четверти).
- ДО/ЛУО разделены (`class.type`), но хранятся в том же каталоге.
- Бенчмарк по всем 6 Soft-метрикам на каждой четверти: `legacy_penalty` (считаем теми же функциями `soft.py` на legacy-слотах) vs `our_penalty` (после `solve`); `wall_ms`, `gap`, `INFEASIBLE` причины.
- UI read-only просмотр legacy по четвертям (грид как в `TimetableGrid`).

**Non-Goals:**
- Импорт всех 8 недель четверти (только 1 недельный шаблон).
- Автоматический мердж ДО/ЛУО в общую модель (раздельно).
- Генерация синтетических Stress-школ (отдельный change).
- XLS → SQLite прямой импорт без JSON-прослойки (JSON обязателен).

## Decisions

- **Недельный шаблон = 2-я неделя четверти (или первая полная 5-дневка).** За 1-й неделей часто пустой Пн (праздник) — берём первую неделю где все 5 дней (`пн..пт`) имеют ≥3 заполненных слотов. Если такой нет — берём мажоритарную ячейку по `(day,period)` среди всех недель четверти. Альтернатива «все 8 недель» отклонена: требование — недельное, 8 недель размывают метрики.
- **Нормализация:** `ФИО` → slug `ivanov_i_i` (транслит + инициалы) + хранение оригинала `display_name`; `предмет` через словарь `SUBJECT_SYNONYMS` (`бейнелеу өнері→ИЗО`, `Дене шынықтыру→Физкультура`, `Әліппе, Ана тілі→Букварь`); `кабинет` → `RoomType` (`начальные→General`, `спортивный→Gym`, `*химия*→ChemistryLab`, `информатика→Informatics`, иначе `General`), `capacity` 30 default, `floor` null.
- **Разделение типов:** `class.type ∈ {normal, do, luo}` парсится из суффикса в строке 0 (`Класс: 5-б ДО`→`do`, `ЛУО`→`luo`). В `catalog.json` поле `type`, в бенчмарке фильтруем по типу (3 отдельных прогона).
- **JSON, не SQLite, как источник truth:** `data/synthetic/catalog.json` + `curriculum_qN.json` + `schedule_legacy_qN.json` (человекочитаемо, `git diff` видно). Заливка в SQLite — отдельная команда `schedule_import_legacy` (транзакция, `DELETE+INSERT` только `schedule_teachers/rooms/classes/subjects/curriculum`, `schedule_slots` не трогает legacy — legacy читается из JSON).
- **Бенчмарк переиспользует `soft.py`:** вместо дублирования метрик считаем `legacy_penalties` теми же функциями, что и `engine.solve` (создаём `CpModel` только для penalty-vars, без `Minimize`). `benchmark.py` на каждом `qN`: `our = solve(curriculum_qN)`, `legacy = eval_penalties(schedule_legacy_qN)` → `benchmark_qN.json` (`legacy_penalty`, `our_penalty`, `delta`, `wall_ms`).
- **Парсер на Python (xlrd), не Rust:** `solver/tools/` уже Python, `xlrd` уже установлен, парсинг 115 файлов — оффлайн утилита, не часть Tauri рантайма. Rust только читает JSON.
- **Комнаты — инференс пула:** если в ячейке нет кабинета — `General`; если пул `required_room_type` (напр. `Химия`) пуст в каталоге — создаём 1 виртуальную `ChemistryLab` чтобы не делать `INFEASIBLE` на этапе импорта (помечаем `synthetic:true`).

## Risks / Trade-offs

- [Risk] Синонимы предметов неполны (казахский/русский) → `unknown` предметы → `sanitary_weight` default 5 → СанПиН исказится. Mitigation: словарь 40+ синонимов + лог `unknown_subjects` в `benchmark` + ручной маппинг.
- [Risk] Недельный шаблон мажоритарным голосованием может взять артефакт (замена в одну неделю). Mitigation: берём 2-ю полную неделю, а не голосование; при сомнении — ручной `overrides.json`.
- [Risk] ФИО дубли (Иванов И.И. в разных предметах — один учитель или два?) → считаем один `teacher_id` по slug, нагрузка суммируется — может превысить `availability`. Mitigation: `build_infeasible_core` укажет, бенчмарк покажет.
- [Risk] 115 файлов × 8 недель = 460 недель парсинга — медленно. Mitigation: парсим только строку 1 `quarter` + 2-ю неделю, кэш `catalog.json`.
- [Risk] `data/synthetic` в git раздует репо (~115×JSON ~2MB). Mitigation: храним только 9 сводных JSON, исходные `.xls` не коммитим (уже в `Materials/`).
