## Why

Сейчас качество расписания настраивается 6 ползунками весов 0..1000 (`WeightsTab`). В реальной доработке
(V33 → V53) пользователь ни разу не говорил числами. Он говорил приоритетами и жёсткостью:
«СанПиН важнее окон», «ученица на инклюзии важнее моих обменов кабинетами», «сдвиг урока — дорого»,
«одно окно можно, два подряд — нет», «это только пожелание». Перевод этих фраз в веса делался вручную и приводил
к ошибкам: обмены кабинетами выросли с 3 до 7 незаметно, потому что их вес был мелким и их не было в сводке;
жёсткий потолок СанПиН не давал солверу стартовать.

К тому же в исследовательской модели правил уже около 40 (СанПиН-кривая, позиция трудных уроков, окна,
сдвоенные окна, день ради одного урока, чередование, три языка, залы, обмены, стабильность…). Шесть ползунков
не выражают этого.

## What Changes

- **Каталог правил**: каждое правило — карточка с понятным названием, пояснением, примером, единицей измерения
  («окно», «балл СанПиН», «сдвинутый урок») и областью действия (школа / класс / учитель / ученик).
- **Режим правила**: `Обязательно` (жёстко) / `По возможности` (мягко) / `Выключено`.
- **Приоритеты вместо весов**: мягкие правила раскладываются по 5 уровням
  («Критично», «Важно», «Желательно», «Мелочь», «Почти не важно»). Уровни переводятся в веса автоматически,
  с запасом, при котором нарушение правила уровня выше «дороже» любого разумного числа нарушений уровнем ниже.
- **Порядок внутри уровня** — перетаскиванием; числа видны только в режиме «Эксперт».
- **Потолок «не хуже базы»**: для любой метрики (СанПиН, окна, обмены) можно задать «не хуже версии X»; реализуется
  мягким потолком с очень большим штрафом (жёсткий мешал солверу стартовать).
- **Переопределения по области**: правило можно усилить/ослабить для класса, учителя, ученика (ссылается на
  пожелания из `schedule-school-profile`).
- **Пресеты**: «СанПиН прежде всего», «Удобство учителей», «Минимум изменений», «Как в прошлом году».
- **Сводка по правилам** в результате генерации: для каждого правила — число нарушений, из них неизбежных,
  и сравнение с базовой версией; «сторожевые» метрики (обмены, поздние старты) показываются всегда, даже если
  правило выключено.

## Capabilities

### New Capabilities
- `schedule-rules-catalog`: каталог правил генерации, режимы, приоритеты, пресеты, сводка по правилам.

### Modified Capabilities
- `schedule`: `WeightsTab` заменяется экраном «Правила»; вход солвера — список правил вместо 6 весов;
  `ScheduleQualityWidget` дополняется сводкой по правилам.

## Impact

- `0026_rule_settings.sql` — `schedule_rule_catalog` (справочник, seed), `schedule_rule_settings` (режим, уровень,
  порядок, параметры, переопределения) на уровне профиля школы и, опционально, варианта.
- `solver/rules/registry.py` — реестр правил: код ↔ ограничение ↔ метрика ↔ проверка.
- `Desktop/src/domains/schedule/ui/RulesTab.tsx`, `RuleCard.tsx`, `PriorityBoard.tsx`, `RuleSummary.tsx`.
- Миграция старых весов: 6 ползунков → уровни (см. design).

## Non-goals

- Сами новые правила ролей — в `schedule-school-profile`.
- Сравнение версий и отчёты по ролям — в `schedule-compare-and-reports`.
