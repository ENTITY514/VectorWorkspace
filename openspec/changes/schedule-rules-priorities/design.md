# Design: Каталог правил и приоритеты

## Context

Опыт V42–V53: одни и те же требования задавались то жёстко, то мягко («1-й урок Ольги Викторовны — сначала
жёстко, потом мягко, сравнить»), а веса подбирались экспериментами (V45: сдвиг ≈ окну, V47: сдвиг ×3,
V49: СанПиН ×1.5). Пользователь хочет управлять смыслом, а не числами.

## Модель данных

```
schedule_rule_catalog(code PK, title, description, example, category, unit,
                      supports_hard INTEGER, supports_soft INTEGER, default_mode, default_tier, params_schema_json)

schedule_rule_settings(id, scope TEXT ('profile','variant'), scope_id, rule_code FK,
                       mode TEXT ('hard','soft','off'), tier INTEGER 1..5, order_in_tier INTEGER,
                       params_json, overrides_json,  -- [{target:{type:'class'|'teacher'|'student',id}, mode, tier, params}]
                       updated_at)
```

Вариант MAY переопределить настройки профиля (например, «доработка» включает `stability`).

## Перевод уровней в веса

- Каждой единице правила назначается «стоимость» `cost = base(tier) × unit_scale(rule) × order_factor`.
- `base(tier)`: 1 → 10 000, 2 → 1 000, 3 → 100, 4 → 10, 5 → 1 (шаг ×10). Шаг выбран так, чтобы в типичной
  школе суммарные нарушения уровня ниже редко превышали одно нарушение уровня выше. Это приближение к
  лексикографической оптимизации без многократных решений.
- `unit_scale` нормирует единицы: 1 балл СанПиН ≈ 1 окно ≈ 1 сдвиг ≈ 1 обмен (по умолчанию), переопределяется
  в режиме «Эксперт».
- `order_factor` внутри уровня: 1.0, 0.9, 0.8 … по порядку перетаскивания.
- Режим **«Строгий порядок»** (опция): последовательные решения по уровням — сначала оптимизировать уровень 1,
  зафиксировать его значение как потолок, затем уровень 2 и т. д. Дороже по времени, используется для
  финальной версии.

## Потолок «не хуже базы»

`base_cap_<metric>` берёт значение метрики базовой версии, пересчитанное той же меркой (важно: одна мерка для
всех версий), и добавляет мягкий потолок: `over ≥ metric − cap`, штраф `over × base(1) × 10`. Жёсткий потолок
не используется: при старте от невыполнимой подсказки солвер не находил решения (V43).

## Сводка по правилам (результат генерации)

```
┌ Правила — V53 против базы V36 ────────────────────────────────────────┐
│ Обязательные: все выполнены ✅                                          │
│ Критично   СанПиН (кривая+позиции)  1139 балл  база 1169  ▼ 2,6 %     │
│ Важно      Окна учителей             82        база 95    ▼ 13        │
│            Сдвоенные окна            15        база 20                │
│            День ради одного урока     5        база 13                │
│            Сдвиг от базы             88 урок                           │
│ Желательно Чередование пар            8 (неизбежно 2)  база 12        │
│            Обмены кабинетами          6        база 3   ▲ ⚠ сторож    │
│ …                                                                     │
└───────────────────────────────────────────────────────────────────────┘
```

- «Неизбежно» считается анализом часов (соотношение часов, сдвоенные уроки, закрепления).
- **Сторожевые метрики** (обмены, поздние старты, 7-е уроки, окна классных руководителей с 1-го урока) показываются
  всегда; рост относительно базы подсвечивается, даже если правило выключено.

## UI — экран «Правила» (вместо «Веса»)

```
┌ Правила генерации ─────────────── Пресет: [СанПиН прежде всего ▾]  [Эксперт ☐] ┐
│ ОБЯЗАТЕЛЬНО                                                                      │
│  ▣ Нет окон у детей   ▣ Класс с 1-го урока   ▣ Режим работы учителей   …        │
├─ КРИТИЧНО ─────────────────────────────────────────────────────────────────────┤
│  ≡ СанПиН: кривая дня         ≡ СанПиН: трудные уроки на 2–4                    │
├─ ВАЖНО ────────────────────────────────────────────────────────────────────────┤
│  ≡ Окна учителей   ≡ Два окна подряд   ≡ День ради одного урока   ≡ Сдвиг от базы│
├─ ЖЕЛАТЕЛЬНО ─── МЕЛОЧЬ ─── ПОЧТИ НЕ ВАЖНО ─── ВЫКЛЮЧЕНО ───────────────────────┤
└──────────────────────────────────────────────────────────────────────────────────┘
```

- Карточка перетаскивается между уровнями; клик открывает панель: пояснение, пример «было / станет», параметры
  (например, «окон без штрафа: 4»), переопределения по классам/учителям, режим «Обязательно / По возможности / Выкл».
- При переводе правила в «Обязательно» система предлагает сразу проверить выполнимость (быстрая проверка до
  60 с; см. `schedule-what-if`).
- Пресеты — наборы настроек; изменение после пресета помечает «Пресет изменён».

## Миграция старых весов

| Старый вес | Правило | Уровень |
|---|---|---|
| `window` | `teacher_windows` | Важно |
| `sanpin_parabola` | `sanpin_day_curve`, `sanpin_heavy_position` | Критично |
| `alternation` | `pair_alternation`, `natural_same_day` | Желательно |
| `load_balance` | `class_load_balance` | Желательно |
| `room_displacement`, `movement` | `room_changes` | Мелочь |
| `change_slot` | `stability` | Важно при >0, иначе Выкл |

Вес 0 → «Выключено». Порядок внутри уровня — по величине старого веса.

## Risks

- Шаг ×10 между уровнями может быть недостаточен в больших школах. Смягчение: режим «Строгий порядок» и
  автоматическая проверка «правило уровня N ухудшено ради уровня N+1» в сводке.
- Много обязательных правил → невыполнимость. Смягчение: быстрая проверка при переключении + объяснение
  (`schedule-what-if`).
