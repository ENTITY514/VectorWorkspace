## Context

Текущий `GridTab` имеет одно поле ввода для фильтрации, которое ищет по `class_id/teacher_id/room_id` через `includes()`. CRUD-вкладки не имеют поиска. Фильтры не сохраняются между переключениями вкладок.

## Goals / Non-Goals

**Goals:**
- Множественная фильтрация с визуальными чипсами
- Быстрые пресеты для типичных сценариев
- Поиск в справочниках при >5 записях
- Сохранение фильтров при переключении вкладок

**Non-Goals:**
- Сохранение фильтров в localStorage (ឋызын булдир)
- Асинхронная фильтрация (данные уже в памяти)
- Фильтрация по периоду (часу) — это Фаза 4

## Decisions

### D1: Фильтры как React state в GridTab

**Решение:** Состояние фильтров хранится в `GridTab` через `useState<FilterState>`. При изменении фильтра — пересчёт `filteredSlots` через `useMemo`.

**Альтернативы:**
- URL параметры — избыточно для десктопного приложения
- Context/Redux — нет необходимости, данные локальны

### D2: Выпадающие списки для выбора значений

**Решение:** Для Класса/Предмета/Учителя/Кабинета — `<select>` с опциями из `state`. Для Дня — кнопки-переключатели (Пн–Сб). Для Смены/Подгруппы — кнопки.

**Альтернативы:**
- Multi-select библиотека — нет в проекте, избыточно
- Автокомплит — данные статичны, select достаточно

### D3: Пресеты через вычисляемые фильтры

**Решение:** Пресеты — функции, которые устанавливают набор фильтров. «Мой день» = `{ day: [currentDay] }`. «Без окон» = вычисление на лету (проверка смежности).

## Risks / Trade-offs

- **[Риск]** Производительность при большом количестве слотов → **Митигация:** Данные уже в памяти, фильтрация <1ms для 1000 слотов
- **[Trade-off]** Select vs multi-select — select проще, но выбор нескольких значений требует зажатия Ctrl → Приемлемо для десктопа
