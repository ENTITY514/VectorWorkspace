## Context

Текущий `BenchmarkView` содержит хардкод данных. `ScheduleDashboard` показывает только readiness и количество слотов. Нет детализации метрик, нет экспорта, нет аналитики по учителям/классам.

## Goals / Non-Goals

**Goals:**
- Детализация метрик в таблице сравнения
- Загрузка реальных данных бенчмарка
- Сводка после генерации
- Экспорт CSV/JSON
- Аналитика по учителю и классу

**Non-Goals:**
- Графики (Recharts) — это отдельная фаза
- Экспорт в XLSX — пока CSV/JSON
- Сохранение отчётов

## Decisions

### D1: Загрузка benchmark_summary.json

**Решение:** Использовать Tauri FS plugin для чтения файла из `data/synthetic/`. Fallback на хардкод если файл недоступен.

### D2: Экспорт через Tauri команду

**Решение:** Использовать существующую команду `schedule_export` (CSV/JSON) из `commands/schedule.rs`. Подключить в `api.ts`.

### D3: Аналитика через вычисления на клиенте

**Решение:** Все метрики вычисляются из `state.slots` на клиенте. Нет дополнительных запросов к бэкенду.

## Risks / Trade-offs

- **[Риск]** Файл benchmark_summary.json может отсутствовать → **Митигация:** Fallback на хардкод
- **[Trade-off]** Аналитика на клиенте vs сервере → Данные уже в памяти, вычисления простые
