## 1. Главный вывод

Найдена **корневая причина** того, почему половина работы делалась Python-скриптами: продуктовый путь генерации (React → Rust → солвер) **не работал на реальных данных вообще** — не из-за архитектуры, а из-за трёх дефектов, каждый из которых по отдельности выглядел безобидно.

| Дефект | Почему был невидим |
|---|---|
| `stdin` читался в cp1251, а не UTF-8 | JSON с кириллическими ФИО не разбирался → `INVALID_INPUT`. Скрипты вызывают `solve()` импортом и stdin не касаются, поэтому у них всё работало |
| Таймаут возвращался как `INFEASIBLE` | Пользователь видел «расписание невозможно» там, где не хватило времени, и считал свои данные противоречивыми |
| Жёсткое ограничение по кабинетам молча отключалось | Эвристика «модель > 80 000 переменных → пропустить H4b» срабатывала на боевом размере **всегда** |

После исправления первого дефекта солвер **впервые отработал на боевых данных из продуктового пути** — 651 слот, статус FEASIBLE.

## 4. Контрольная точка: НЕ пройдена

Честный результат: генерация продуктовым путём на боевых данных **не сходится за разумное время** при корректном ограничении по кабинетам.

| Конфигурация | Результат |
|---|---|
| H4b отключён (как было) | FEASIBLE, 651 слот, ~60 с — но с накладками кабинетов |
| H4b корректен | TIME_LIMIT при 90 / 180 / 240 / 300 с |
| H4b корректен + подсказка из предыдущего расписания | TIME_LIMIT |

### Причина

**Ни у одного из 39 учителей не задан базовый кабинет.** 524 урока × 58 взаимозаменяемых кабинетов — комбинаторный взрыв: почти каждый урок можно поставить в любой кабинет, и варианты для солвера неразличимы.

Проверенная гипотеза: я реализовал кабинетную систему (при заданном `base_room_id` обычные уроки идут в кабинет учителя) и назначил кабинеты round-robin в копии базы. Результат — **настоящий INFEASIBLE**: 39 учителей на 23 общих кабинета означает, что двое делят кабинет и не могут вести одновременно.

**Вывод: нужны данные о привязке кабинетов, и назначить их автоматически нельзя.** Это решение о том, как устроена школа, а не программный дефект.

### Что это меняет для вас

Раньше генерация из UI не работала **вообще** (не разбирался кириллический ввод). Сейчас она работает, но упирается в недостающие данные — и сообщает об этом внятно:

```
статус : TIME_LIMIT
warning: TIME_LIMIT: решение не найдено за 90 с. Это НЕ доказательство
         невозможности расписания.
warning: NO_BASE_ROOMS: ни у одного из 39 учителей не задан базовый кабинет,
         а кабинетов 58. Почти каждый урок можно поставить в любой кабинет,
         поэтому перебор размещений огромен.
```
