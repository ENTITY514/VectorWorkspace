**Приоритет:** P0  
**Оценка:** 5 дней  
**Зависит от:** карантин MCP уже в ядре  
**Разблокирует:** смысл [истории версий](./06_version_history.md) и [рефлексии](./04_lesson_reflection.md) для агента

## Проблема сейчас

MCP читает и правит КТП/КСП: `mcp_list_tools` / `mcp_invoke`, карантин в RAM, `ktp_commit_staged` / `ksp_commit_staged`, связка `lesson_get_bundle`. Фронт умеет вызвать те же команды (`api.ts`), но экрана нет.

`docs/08-mcp-core.md` уже требует «визуальный дифф в React UI перед сохранением». Сейчас дифф есть только у оператора Cursor. Учитель карантин не видит и не подтверждает.

Писать в SQLite в обход карантина нельзя: шапка КСП жёстко из КТП, правки без превью ломают доверие.

## Что делаем

Панель рядом с уроком (КТП и КСП), не отдельный «чатбот на всё приложение».

- Контекст всегда конкретный: `planId`, `lessonId`, `kspId`. Старт — `lesson_get_bundle`.
- Сообщения учителя → провайдер (ключ из настроек / OS keyring, как в доке MCP) → вызовы `mcp_invoke`.
- Мутации только в карантин. После ответа агента — карточка diff: тема, цели, этапы, ДЗ, пометка «черновик».
- Кнопки «принять» / «отклонить» = `*_commit_staged` / `*_discard_staged`. Несколько артефактов — список, не молчаливый commit всего.
- Если редактор КСП грязный — сначала сохранить или отменить, затем пускать агента.
- Тему и цели ТУП агент меняет только через `ktp_update_lesson` / `ktp_set_lesson_objectives`, не через шапку КСП.

Провайдер и ключ — в настройки, не в репозиторий. Пока ключа нет, панель показывает список инструментов и ручной вызов (отладка), без «разговора».

## Критерий приёмки

С карточки урока учитель пишет «собери КСП», видит карантин этапов, жмёт «принять» — документ в БД, валидатор V-xx тот же, что в редакторе. «Отклонить» оставляет БД нетронутой. Повторная правка того же КСП копит один staged-артефакт, не затирает предыдущий черновик. Смена темы в чате меняет урок КТП и подтягивает шапку КСП только после commit КТП.
