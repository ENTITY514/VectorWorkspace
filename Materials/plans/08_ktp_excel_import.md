# План 8. Импорт КТП из Excel

**Приоритет:** P2  
**Оценка:** 4 дня  
**Зависит от:** [экспорт КТП](./01_ktp_export.md) — сначала свой шаблон, потом круг  
**Опора:** `generate_ktp_from_tup`, инварианты СОР/СОЧ, UX импорта расписания

## Проблема сейчас

ТУП грузится из HTML/JSON (`TupImportPanel`). КТП обычно **генерируется из ТУП**. В школах календарь уже живёт в Excel (свой файл или выгрузка Кунделик). Без импорта учитель набивает заново то, что есть на диске.

Расписание уже открывает `.xlsx` через `@tauri-apps/plugin-dialog` (`domains/schedule/ui/ImportPanel.tsx`) — жест знакомый. Импорта плана уроков нет.

Обещать «любой файл завуча» нельзя: колонки пляшут. Два профиля реалистичны: **наш экспорт** и **Кунделик**. Остальное — ручное сопоставление колонок.

## Что делаем

Мастер на странице КТП:

1. Выбрать `.xlsx`.
2. Профиль: «наш шаблон» (колонки как в плане 1) или «Кунделик».
3. Превью первых строк, ошибки (пустая тема, дата не парсится, неизвестный тип).
4. Сшить цели по коду с загруженным ТУП; нет кода — оставить текстом и пометить.
5. Создать **новый** план. Существующий не затирать без явного «заменить этот план».
6. Прогнать те же инварианты часов и СОР/СОЧ, что после `generate_ktp_from_tup`. Показать отчёт, не прятать.

Парсинг — в Rust или в том же слое, что `xlsx-generator` (лист → строки уроков). Не скрипт в `scripts/`.

Импорт не создаёт КСП автоматически. После плана учитель идёт в каталог КСП или в чат.

## Критерий приёмки

Excel, только что выгруженный кнопкой плана 1, импортируется в новый план: число уроков, даты, типы СОР/СОЧ совпадают, инварианты те же. Повреждённый лист останавливается на превью с номером строки, база не пишется. Повторный импорт того же файла без «заменить» создаёт второй план, не портит первый.
