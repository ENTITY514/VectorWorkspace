## Проблема сейчас

Пункт меню «Аналитика» — про расписание: окна, СанПиН, кабинеты (`panels/Analytics.tsx`). Это не покрытие документов.

`KtpProgressPanel` считает уроки **с датой**, не с КСП. У агента уже есть `ktp_get_section_progress` (дата + наличие КСП) — учителю этого экрана нет.

Цифры нельзя считать только во фронте: те же метрики нужны MCP и тестам. Аналитика расписания уже следует этому правилу.

## Что делаем

Экран на выбранный план (фильтр: предмет, класс, год):

- нет КСП;
- КСП-черновик с блокирующими V-xx;
- готов / утверждён / проведён;
- цели ТУП, ни разу не вышедшие в урок;
- разделы: часы по плану vs число уроков с датой;
- СОР/СОЧ по четвертям (опереться на инварианты КТП).

Клик ведёт в урок, в создание КСП или в редактор черновика. Блок «к следующей неделе» — уроки с датой в ближайшие 7 дней без статуса `ready` и выше.

Пункт «Аналитика» разделить: расписание / покрытие документов. Либо вкладка на странице КТП над списком планов — если отдельный пункт путает.

Команда Rust: `ktp_coverage_report { planId }` → те же поля, что видит UI и что может вернуть MCP (`ktp_get_coverage`).

## Критерий приёмки

Для плана из N уроков сумма «нет КСП + есть КСП» равна N. Урок без документа попадает в «нет КСП». Черновик с V-03 (нет этапов) — в «не готов». Клик по строке открывает тот же урок, что каталог КСП. Повторный запрос после создания КСП сдвигает счётчики без перезапуска приложения.
